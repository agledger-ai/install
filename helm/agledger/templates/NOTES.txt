Pre-upgrade backup:
  No backup ran this time. Helm finishes every pre-upgrade hook before it
  creates an ordinary resource, so the PersistentVolumeClaim this release just
  created did not exist when the hook would have run. It does now, and the next
  `helm upgrade` takes a backup before the migration. Scheduling the hook
  against a claim that is not there yet does not fail fast: the pod stays
  Pending and the upgrade blocks until its timeout.

{{- if not .Values.image.digest }}

Image pin (production hardening):
  Your deployment pulls `{{ .Values.image.repository }}:{{ default .Chart.AppVersion .Values.image.tag }}` with
  `pullPolicy: {{ .Values.image.pullPolicy }}`. Kubelet's tag-name cache means a node that
  previously pulled ANY image under this tag will NOT re-pull on the next
  deploy: pods can silently boot against stale layers when a tag is
  re-pushed. For production, pin by content hash:

    helm upgrade ... \
      --set image.digest="sha256:<digest-from-registry>" \
      --set image.tag="{{ default .Chart.AppVersion .Values.image.tag }}"   # cosmetic when digest is set

  Look up the current digest:
    docker buildx imagetools inspect {{ .Values.image.repository }}:{{ default .Chart.AppVersion .Values.image.tag }}
{{- end }}
